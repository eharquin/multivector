# MultiVector 0.1.0 Release Notes

- **Status:** Stable release
- **Tracking issue:** [#96](https://github.com/eharquin/multivector/issues/96)
- **Planned tag:** `v0.1.0`
- **Release date:** 2026-09-13
- **Acceptance:** [VGA 2D Visual Workflow Acceptance Record](../acceptance/vga-2d-visual-workflow.md)

MultiVector 0.1.0 is the first reusable release of the browser-based research
environment. It establishes a stable workflow for authoring, evaluating,
visualizing, manipulating, and saving constructions in two-dimensional
vectorial geometric algebra, VGA(2).

## Highlights

- Named multivector expressions, forward references, dependency evaluation,
  localized diagnostics, lists, ranges, indexing, and broadcasting.
- Fundamental VGA(2) products and involutions, grade and coefficient access,
  rotors, exponential forms, powers, inverse, division, norm, normalization,
  and sandwich transformations.
- Positioned vector and bivector visualization with appearance, labels,
  viewport navigation, display settings, and light, dark, or system themes.
- Pointer and keyboard creation and manipulation with bounded undo and redo,
  gesture cancellation, and dynamic base or head anchoring.
- Direct scalar controls with deterministic once, loop, and ping-pong playback.
- Local document persistence plus validated canonical JSON import and export.
- Automated type, lint, test, build, deployment, and HTTP smoke workflows.

## Verification status

The automated project suite passes with 25 test files and 326 tests on the
release commit. The supported-browser matrix is recorded in the acceptance
record; the deployed-artifact checks are recorded there after publication.

## Known scope and limitations

- The release supports VGA(2). PGA and other algebra families remain roadmap
  work.
- Supported browsers: current Google Chrome and Mozilla Firefox on Linux
  desktops with mouse or trackpad input, and Safari 17.6 on macOS 12.7 with
  trackpad input, at standard and HiDPI density, as recorded in the
  acceptance matrix ([#89](https://github.com/eharquin/multivector/issues/89)).
  Microsoft Edge, touch input (including touchscreen pinch,
  [#120](https://github.com/eharquin/multivector/issues/120)), and mobile
  browsers are not claimed.
- Undoing a viewport gesture moves keyboard focus to the last edited
  expression rather than back to the viewport
  ([#115](https://github.com/eharquin/multivector/issues/115)), and keyboard
  handle steps are fixed mathematical units rather than scaled with the zoom
  ([#118](https://github.com/eharquin/multivector/issues/118)); pointer
  manipulation and Shift-stepped keys work around both.
- When several objects share a base point, the topmost handle receives the
  press and the anchor snap zone re-attaches objects released within 22 px;
  the default rotation example places `V1`, `V2`, and `B` at the origin and
  therefore exhibits this on first use. Tracked by
  [#100](https://github.com/eharquin/multivector/issues/100) and deferred.
- Construction provenance and positioning for derived or list-contained
  bivectors remain design questions tracked by
  [#85](https://github.com/eharquin/multivector/issues/85),
  [#87](https://github.com/eharquin/multivector/issues/87), and
  [#88](https://github.com/eharquin/multivector/issues/88).
- Documents are stored in the active browser or exchanged as files. URL
  sharing, collaborative storage, and figure export are not included.
